## 系統擴展性 (Scalability)

### 1. 水平擴展能力

#### 後端服務擴展
- **無狀態設計**: 所有後端服務實例都是無狀態的
- **負載均衡**: 可以通過 Load Balancer 分發請求
- **會話管理**: 使用 JWT Token，無需服務器端會話存儲

```
┌─────────────┐
│ Load        │
│ Balancer    │
└──────┬──────┘
       │
   ┌───┴───┬─────────┬─────────┐
   │       │         │         │
┌──▼──┐ ┌──▼──┐  ┌──▼──┐  ┌──▼──┐
│ BE1 │ │ BE2 │  │ BE3 │  │ BEN │
└─────┘ └─────┘  └─────┘  └─────┘
```

#### Redis 擴展
- **Redis Cluster**: 支持分片和主從複製
- **資料分片**: 可以按商品 ID 分片
- **讀寫分離**: 主節點寫入，從節點讀取

#### 資料庫擴展
- **主從複製**: PostgreSQL 支持主從複製
- **讀寫分離**: 寫操作到主節點，讀操作到從節點
- **連接池**: 使用連接池管理資料庫連接

### 2. 垂直擴展能力

#### 資源監控
- **CPU**: 監控 CPU 使用率，設置閾值告警
- **內存**: 監控內存使用，防止 OOM

#### 性能調優
- **連接池大小**: 根據並發量調整
- **快取策略**: 優化 Redis 快取命中率
- **資料庫索引**: 優化查詢性能

## 一致性保證 (Consistency)

### 1. 強一致性場景

#### 排行榜更新
- **實現**: Lua Script 原子操作
- **保證**: 單線程執行，保證原子性
- **場景**: 出價時更新排行榜

```lua
-- Lua Script 保證原子性
local rank_key = KEYS[1]
local user_id = ARGV[1]
local score = ARGV[2]

-- 原子性更新
redis.call("ZADD", rank_key, score, user_id)
```

#### 庫存檢查
- **實現**: Lua Script 中檢查活動時間
- **保證**: 防止活動結束後繼續出價
- **場景**: 出價時檢查活動狀態

### 2. 最終一致性場景

#### 資料庫寫入
- **實現**: 異步 Goroutine 寫入
- **保證**: 最終會寫入資料庫
- **場景**: 出價記錄異步持久化

```go
// 異步寫入資料庫
go func() {
    s.db.Create(&database.BidLog{
        UserID: userID,
        ProductID: productID,
        Price: price,
        Score: score,
        CreatedAt: time.Now(),
    })
}()
```

#### WebSocket 推送
- **實現**: 異步廣播消息
- **保證**: 最終所有客戶端會收到更新
- **場景**: 排行榜更新推送

### 3. 一致性模型

#### CAP 定理分析
- **Consistency (一致性)**:
  - 排行榜：強一致性（Lua Script）
  - 資料庫：最終一致性（異步寫入）

- **Availability (可用性)**:
  - 高可用（多實例部署）
  - Redis 主從複製 *(目標設計，尚未建置——目前 `docker-compose.yml` 只跑單一 Redis 節點)*
  - 資料庫主從複製 *(目標設計，尚未建置——目前 `docker-compose.yml` 只跑單一 PostgreSQL 節點)*

- **Partition Tolerance (分區容錯)**:
  - Redis Cluster 支持分區 *(目標設計，尚未部署)*
  - 資料庫主從複製支持分區 *(目標設計，尚未部署)*

**選擇**: 優先保證 **Availability** 和 **Partition Tolerance**，在關鍵場景（排行榜）保證 **Consistency**。註：目前實際部署是單一 Redis 實例加單一 PostgreSQL 實例，上述多節點高可用/分區容錯的說法屬於擴展規劃，並非現況。

### 4. 資料一致性驗證

#### 驗證方法
1. **出價記錄數 <= K**: 通過 Lua Script 保證
2. **排行榜用戶數 <= K**: Redis Sorted Set 自動維護
3. **資料庫與 Redis 一致性**: 需要一支定期驗證腳本

> 目前專案中還沒有這支驗證腳本（`loadtest/` 目前只有 `demo_script.py`、`locustfile.py`、`locustfile_demo.py`）。這是建議中的檢查方式，尚未實作。

## 性能優化策略

### 1. 快取策略

#### Redis 快取
- **商品配置**: 快取商品參數（K, alpha, beta, gamma）
- **排行榜**: 即時排行榜（Sorted Set）
- **最高價**: 快取當前最高價

#### 快取更新
- **寫穿透**: 更新時同時更新快取
- **失效策略**: 活動結束後清理快取

### 2. 資料庫優化

#### 索引優化
```sql
-- 用戶表索引
CREATE INDEX idx_users_username ON users(username);

-- 出價記錄索引
CREATE INDEX idx_bid_logs_product ON bid_logs(product_id);
CREATE INDEX idx_bid_logs_user ON bid_logs(user_id);
```

#### 查詢優化
- **分頁查詢**: 避免全表掃描
- **連接池**: 複用資料庫連接
- **批量操作**: 批量寫入出價記錄

### 3. 網絡優化

#### HTTP 優化
- **壓縮**: Gzip 壓縮響應
- **Keep-Alive**: 複用 HTTP 連接
- **CDN**: 靜態資源使用 CDN

#### WebSocket 優化
- **心跳**: 定期發送 Ping/Pong
- **重連**: 指數退避重連策略
- **消息壓縮**: 大消息壓縮傳輸

## 故障恢復

### 1. 故障場景

#### Redis 故障
- **影響**: 排行榜無法更新
- **恢復**: 從資料庫重建排行榜
- **預防（規劃中）**: Redis 主從複製——尚未部署

#### 資料庫故障
- **影響**: 無法持久化資料
- **恢復**: 從 Redis 恢復資料
- **預防（規劃中）**: 資料庫主從複製——尚未部署

#### 服務故障
- **影響**: 服務不可用
- **恢復**: 自動重啟或切換實例
- **預防**: 多實例部署，健康檢查

## 總結

### 擴展性
- ✅ **水平擴展**: API 是無狀態設計，理論上可以在 Load Balancer 後面部署多個後端實例（目前尚未這樣部署）
- 🔲 **叢集/複製擴展**: Redis Cluster 與 PostgreSQL 複本是規劃中的下一步，目前尚未建置
- ✅ **快取優化**: Redis 快取熱點資料（排行榜、商品配置）
- ✅ **資料庫優化**: 已有索引與連接池

### 一致性
- ✅ **強一致性**: 排行榜更新（Lua Script）
- ✅ **最終一致性**: 資料庫寫入（異步）
- 🔲 **資料驗證**: 定期驗證腳本目前只是提議，尚未實作
- 🔲 **故障恢復**: 上述恢復機制是設計草案，尚未實作

### 性能
- 🔲 **上述響應時間／吞吐量／WebSocket 延遲目標**: 僅為設計目標，本專案目前沒有壓測結果可以佐證
